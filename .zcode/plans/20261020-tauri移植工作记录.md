### 阶段1：基础设施桥 — ✅ 完成（2026-10-20）

架构决策（阶段1新增）：
| # | 决策 | 理由 |
|---|---|---|
| D8 | renderer.ts 直接调 @tauri-apps/api（不再经 window 命名空间中转） | 计划 §2 既定方向；类型安全、少一层间接。副作用：Electron webpack 构建的 renderer 不再可用（Electron 侧文件保留但不再被 Tauri 前端引用，D1 共存语义的细化：保留文件 ≠ 保持双栈可构建） |
| D9 | fs 用 plugin-fs + 全盘 scope（capabilities），非自定义 command | 按计划走 plugin 生态，二进制边界（Uint8Array）由 plugin 处理；readFile 渲染层现有调用均为文本场景，实现为 readTextFile |
| D10 | getGlobalContext 保持同步签名：入口 setupGlobalContext() 预热缓存 | 计划要求"sendSync → 启动时 invoke"，同步签名让 6 处调用点零改动 |
| D11 | message-bus：主窗口 invoke sync_app_state（Rust 存储+emit_to 扩展窗口）；扩展窗口→主窗口用前端 emitTo 直连（无需 Rust 中转）；订阅过滤移到扩展窗口前端 | 语义等价、链路最短；Rust 侧 AppState 供阶段5 托盘消费 |
| D12 | **窗口创建必须在独立线程**（std::thread::spawn），不能在 command 线程同步 build | 实测 Windows 上 command 线程同步 WebviewWindowBuilder::build() 与主线程死锁（invoke 永不返回，webview 停在 about:blank）；spawn 后正常 |
| D13 | Electron 版用户配置继承：启动时若新目录无 config.json 且 %APPDATA%/MusicFree/config.json 存在则复制 | 用户从 Electron 版升级不丢配置（计划未明确要求，低成本高体验） |
| D14 | 默认配置双端同源：default-app-config.ts → JSON + re-export，Rust include_str! | 避免默认值漂移 |
