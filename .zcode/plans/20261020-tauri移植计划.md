# MusicFree 桌面版 Electron → Tauri 移植计划

> 基线 commit：`f3b526a`（master，2026-10-20 调查）
> 目标框架：Tauri 2.x（Rust 后端 + WebView2/WebKitGTK 前端），前端构建 webpack(electron-forge) → Vite

## 0. 已确认的决策记录

| 决策点 | 结论 |
|---|---|
| 插件执行环境 | **WebView 内嵌运行时**：插件 JS 在主窗口隐藏 iframe 中执行，白名单依赖打包浏览器版，HTTP 经消息代理交 Rust 转发（无 CORS 限制） |
| Windows 任务栏 | 保留 thumbar 控制按钮（Rust `ITaskbarList3` 重写）；**放弃**专辑封面缩略图（删除 `TaskbarThumbnailManager.node`） |
| 系统媒体控制 | 保留，Rust `souvlaki` crate 实现（Windows SMTC 优先，macOS/Linux 随平台验证） |
| 平台范围 | **Windows 优先**；macOS/Linux 保留编译目标，延后验证 |
| 死代码处置 | 直接删除：`src/shared/database/*`（better-sqlite3 全套，从未接线）、`src/webworkers/db-worker*`、`socket.io` 依赖、`webviewTag` 配置、`renderer/core/downloader/index.new.ts` |

## 1. 可行性结论（调查摘要）

**可行。** 本项目渲染层从不直接 import electron，全部经 `contextBridge` 暴露的 `window["@shared/xxx"]` 命名空间 + `src/shared/*/renderer.ts` 薄封装访问原生能力，隔离良好。约 80-85% 前端代码（React 组件/页面、TrackPlayer 状态机、audio-controller、歌词解析、Dexie/IndexedDB、HashRouter、hotkeys-js、i18next）为纯 Web 代码可平移。

必须重写的部分集中在"无 Node 运行时后怎么办"：
1. 插件执行器（原主进程 `Function()` + 白名单 require）→ WebView iframe 运行时（阶段 3）
2. 带自定义 header 的音频流（原 `webSecurity:false` + `onBeforeSendHeaders` 注入 + fork 的 request-forwarder 子进程）→ Rust 自定义流式协议（阶段 2）
3. 三个 Node worker（下载 fs/stream、chokidar 监听、music-metadata 解析）→ Rust command（阶段 4）
4. MessageChannelMain 端口通信 → Tauri `emit_to` 定向事件（阶段 1）
5. Win32 hookWindowMessage 拖拽 → `data-tauri-drag-region`（阶段 1/6）
6. 任务栏缩略图二进制（无源码）→ 放弃封面，重写按钮（阶段 5）

## 2. 总体架构映射

| Electron 现状 | Tauri 目标 |
|---|---|
| 主进程 (src/main, TS) | Rust core (`src-tauri/`)：commands + 窗口/托盘/协议/系统集成 |
| preload contextBridge | `@tauri-apps/api` + `@tauri-apps/plugin-*`；`shared/*/renderer.ts` 内部实现替换，**导出签名不变，上层组件零改动** |
| 3 窗口 (main/lrc/minimode) | 3 个 `WebviewWindow`（label: `main`/`lrc`/`minimode`），配置见 §4 |
| MessageChannelMain MessagePort | `emit_to(label)` + `EventTarget::labeled`，message-bus 的 preload 层重写、renderer 层接口保持 |
| request-forwarder.js 子进程 + `_setHeaders` hack | Rust `register_asynchronous_uri_scheme_protocol("mediahub")` 流式转发（请求头、代理、basic-auth 在 Rust 侧注入） |
| 主进程 i18n（fs 读 res/lang） | 语言 JSON 打包进前端；托盘等 Rust 侧文案由主窗口通过 command 推送 |
| electron-log | tauri-plugin-log |
| `app.getPath` 系/便携版重定向 | Tauri path API + 启动时检测 exe 旁 `portable/` 目录重定向数据目录 |
| Inno Setup 发版 | Tauri bundler（NSIS），`musicfree://` 协议随安装器注册 |

### 插件运行时架构（核心设计）

```
主窗口 (React)
 ├─ <iframe src="plugin-runtime.html" hidden>   ← 第 4 个 Vite 入口
 │    ├─ require shim（白名单：cheerio/crypto-js/dayjs/big-integer/qs/he/webdav/…浏览器版打包）
 │    ├─ Function() 执行插件源码（与现状同构，非真沙箱，安全水平与 Electron 版持平）
 │    └─ axios polyfill → postMessage 请求代理
 ├─ postMessage 双向 RPC（call-plugin-method / 事件回调，带超时）
 └─ Rust 侧：reqwest 转发（无 CORS、支持代理/忽略证书/超时）+ cookie jar（登录态）+ musicfree/storage（fs JSON）
```

- 插件 hash、`supportedMethod` delegate 协议、安装/更新/卸载流程保持不变（文件管理移到 Rust command）。
- `@react-native-cookies/cookies` polyfill → Rust cookie jar：转发响应收集 `set-cookie`，后续请求自动携带；对外暴露 `get/set` 接口。
- `musicfree/storage` polyfill → localStorage（iframe 同源，10MB 上限逻辑保留）。
- 内部插件 `local-plugin`（本地音源）原在主进程用 music-metadata/fs → 改为 iframe 内调用经 postMessage → 主 frame → Rust command（lofty 解析）。

## 3. 阶段计划

依赖顺序：阶段 0 → 1 → 2 → 3 →（4、5 可并行）→ 6。每阶段以"验收标准"收口。

### 阶段 0：工程骨架
- 新建 Vite 工程（React+TS），3 个 HTML 入口 + `plugin-runtime` 入口（先空壳）；迁移别名（`@`/`@renderer*`/`@shared`）、scss、`@svgr`；`SvgAsset` 的 webpack 动态 require 改 `import.meta.glob`。
- `src-tauri` 初始化；三窗口按 §4 配置创建；`res/`（logo/lang 之外）清理后作为 resources。
- 删除死代码（§0 清单）。
- **验收**：三窗口能打开、UI 渲染正常（功能未接）。

### 阶段 1：基础设施桥
- app-config：Rust command（JSON 读写，保留迁移逻辑）+ `update-app-config` 事件广播；`shared/app-config/renderer.ts` 内部改 invoke/listen。
- global-context：`sendSync` → 启动时 `invoke`（async），workersPath 字段随 worker 移除一并删除。
- message-bus 重写：13 条命令 + AppState（musicItem/playerState/repeatMode/lyricText）经 Tauri 事件定向；`renderer/main.ts`、`renderer/extension.ts` 保持导出。
- utils/renderer.ts：fs → `plugin-fs`；dialog → `plugin-dialog`；shell → `plugin-opener`；appWindow（最小化/显示/歌词窗/迷你窗/穿透/最大化切换）→ WebviewWindow API + Rust command。
- 窗口拖拽：`data-tauri-drag-region`；日志：tauri-plugin-log；单实例 + 深链插件挂载。
- **验收**：设置页读写持久化；迷你模式/歌词窗开关与主窗互切正常；窗口位置记忆。

### 阶段 2：媒体管线（最高技术风险）
- Rust `mediahub://` 流式协议统一三条现路径：
  1. 本地文件（原 file://）；
  2. 带自定义 header/UA 的远程音频（原 `_setHeaders` + forwarder）；
  3. basic-auth URL（原 Authorization 转换）。
  URL 编码目标地址与 header，Rust 端 reqwest 拉流 `respond`；支持 Range 透传（拖动进度）。
- hls.js：m3u8 及分片同样经协议转发（playlist 重写分片 URL 或由代理透明完成）。
- audio-controller 适配：`src` 统一 `convertFileSrc`/协议改写；删除 fetch→blob→objectURL 分支。
- SMTC：souvlaki（Windows），播放状态/元数据由 audio-controller 回调上报 Rust。
- **验收**：本地文件播放/拖动进度；模拟 header 注入源播放；媒体键/系统音量面板控制。

### 阶段 3：插件运行时（最大工作量）
- §2 架构落地：plugin-runtime iframe、require shim、白名单包浏览器版打包（注意 cheerio 浏览器 bundle 体积与性能，必要时 worker 化）。
- axios polyfill 请求代理（超时/中断/进度对齐现有插件用法）；cookie jar；storage polyfill。
- 插件管理 Rust command：远程/本地/清单安装（nanoid 命名）、卸载（删除目录）、更新、`call-plugin-method` 桥接（主 frame ↔ iframe postMessage，Promise + 超时）。
- 代理配置（network.proxy.*）应用到 Rust 请求端（插件下载 + 音频转发）；忽略证书校验选项保留。
- **验收**：社区主流音源插件安装→搜索→播放→歌词→歌单全链路；插件登录态（cookie）有效；WebDAV 备份/恢复。

### 阶段 4：本地音乐、下载与主题
- 下载器：Rust command（并发队列对齐 PQueue 语义、进度事件、basic-auth、m3u8 整源下载场景）。
- 本地导入：拖放（Tauri `onDragDropEvent` 取路径，替代 `File.path`）+ 目录选择。
- 目录监听：`notify` crate（watch 深度对齐 chokidar depth 10）。
- 元数据：`lofty` 解析标签；GBK/GB2312 编码检测用 `encoding_rs` + `chardetng`（替代 jschardet+iconv-lite）；伴生 `.lrc/.txt` 歌词读取 Rust command。
- 主题包：`.mftheme`(zip) Rust 解压；CSS 注入与 iframe 主题（web 侧逻辑保留，`@/` 别名 → asset 协议 URL）。
- **验收**：本地目录扫描入库、播放、编码正确的歌词；下载队列完整；主题安装/切换/卸载。

### 阶段 5：系统集成
- 托盘 + 动态菜单（歌名/播放控制/循环模式 radio 子菜单，随播放状态重建）；macOS 状态栏歌词（tray title）随平台验证。
- 全局快捷键（8 个可配置项，快捷键串格式转换）。
- thumbar 按钮：Rust `windows` crate `ITaskbarList3`（上一首/播放暂停/下一首）。
- 深链 `musicfree://install/...` 解析复用现有逻辑（纯 URL 解析，零改动）。
- 便携版：启动时检测 exe 旁 `portable/` 重定向数据目录（Rust 侧 path resolver）。
- 更新检查：保留 version.json 比对逻辑（Rust reqwest）。
- **验收**：托盘全操作、快捷键、任务栏按钮、深链安装插件、便携包数据独立。

### 阶段 6：打磨与发版
- 桌面歌词细节：锁定态 hover 动态穿透（mousemove → invoke `set_ignore_cursor_events`，替代 forward:true）、字号↔窗口高度联动、多显示器边界归一化。
- 缓存清理：改清 WebView2/应用数据目录（原 `session.clearCache`）。
- `setSinkId` 输出设备切换在 WebView2 的可用性验证（不支持则明确降级提示）。
- CSP 定稿（插件 iframe、主题 iframe、远程图片、媒体协议白名单）。
- NSIS 安装器（协议注册、图标、中文）；签名；启动速度/内存/包体积对比 Electron 版并记录。
- 全功能回归清单过一遍（以 §4 矩阵为准）。

## 5. 风险与预案

| 风险 | 等级 | 预案 |
|---|---|---|
| cheerio 浏览器版在大歌单 HTML 解析下性能不足 | 中 | 先实测；不达标时插件运行时 worker 化，或对重插件回退 Rust QuickJS 方案（决策点已选 WebView，QuickJS 为后备） |
| WebView2 透明窗口（歌词窗）性能/合成问题 | 中 | 实测帧率；不达标时半透明纯色背景降级 |
| mediahub 协议 Range/流式中断边界（拖动、切歌） | 中 | 阶段 2 首先验证 Range 透传；保留"先下载后播"降级路径 |
| 插件登录态 cookie 语义差异（域匹配/过期） | 中 | cookie jar 实现按 domain/path 简化匹配，对照Electron session 行为补齐 |
| hover 动态穿透体验不如 forward:true | 低 | 接受轻微延迟；或锁定态完全穿透 + 显式解锁按钮 |
| 主题包第三方 iframe 受 CSP 限制 | 低 | asset 协议白名单放行主题目录 |
| macOS/Linux 未验证项 | 已决策延后 | invalidateShadow、Linux 托盘单击行为、MPRIS 等列入平台跟进清单 |
